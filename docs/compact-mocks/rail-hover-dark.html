Why does the reconnect test fail one run in five on CI? Check upstream for the known race and fix it.
The race is a known one: the discussion is at https://github.com/swiftlang/swift/issues/74189, and the CI side — jobs running the reconnect suite in parallel on the same runner — is covered in https://docs.github.com/en/actions/using-jobs/using-concurrency. The backoff rule we want to pin is the one in https://datatracker.ietf.org/doc/html/rfc6298: double the interval on each failure, never shrink it on a retry.
The UDP usage guidelines make the same point about retry ceilings: https://www.rfc-editor.org/rfc/rfc8085. I am pinning the jitter factor to 1.0 in the test so the assertion measures the backoff and not the dice.
